# 2026-10 这批更新的上线验收清单

> 状态：active

部署后照着点一遍，大约 30 分钟。每一项写了「怎么做 → 应该看到什么」。
**对不上的，把那一屏截图，连同页面上的提示原话一起发回来。**

本地已经验证过的不在这里重复；这张清单只管两类事：线上环境才能确认的，和上线后团队第一天最容易撞到的。

## 0. 部署

```bash
cd /opt/ferr-ops && git pull origin main && sudo docker compose up -d --build
```

- 启动时会自动加几张新表和几个新列，不动已有数据。
- 部署前把 `docs/TEAM_CHANGES_2026-10.md` 发给李和陈。

## 1. 先确认没有坏（5 分钟）

用老板账号登录，依次点开：总览、KPI 考核、询盘评级、数据看板、投入台账、计划 / 总结、测试 / 整改、周度审核、关键词库、归档、设置。

- [ ] 每一页都能打开，数字和图表与更新前一致（总览的询盘趋势、KPI 的圆环、数据看板的表格）。
- [ ] 没有哪一页是空白或一直转圈。

## 2. 任务完成门槛（用李的账号）

- [ ] 日计划里新建一条普通任务 → 勾完成 → **弹出完成框**。不填结果直接提交 → 被拒，提示要写完成结果。
- [ ] 填「已上线新标题」→ 提交成功，卡片打勾。
- [ ] 再建一条任务，把「重要度」选成重要任务 → 勾完成，只填结果不给证据 → 被拒，提示重要任务需要证据。贴一个链接后提交成功。
- [ ] 在已完成的那条上点「改」，把结果删空再保存 → 被拒。
- [ ] 把一条任务的标题改一下、截止日往后挪一天 → 卡片上出现「改 2」，点开能看到两条记录（谁、什么时候、从什么改成什么）。
- [ ] 建一条跨天任务（开始日早于截止日）→ 再把它改成同一天 → 卡片上「重要」还在，悬停显示「原本是跨天任务」；这时勾完成不给证据 → 被拒。

## 3. 询盘确认（先李，后经理 / 老板）

- [ ] 李录一条询盘 → 渠道格下面显示**待确认**。
- [ ] 经理 / 老板登录 → 这条询盘行尾有一个打勾的小按钮（悬停显示「确认这条询盘的渠道与等级」），点它 → 变成**已确认**，渠道和等级变成带锁的标签。
- [ ] 换回李 → 这条询盘的渠道、等级点不动；点删除 → 提示「这条询盘已经确认，要删除（归档）请找经理或老板」。
- [ ] 经理点那个带锁的等级标签 → 弹出修改框，把 A 改成 B，**不填原因提交不了**；填了之后行上出现「改 1」，点开能看到是谁、什么时候、为什么改的。
- [ ] 表格上方有确认进度（已确认多少 / 待确认多少）。

## 4. 周度审核（经理 / 老板）

- [ ] 打开「周度审核」，选上周 → 任务、数据、询盘质量、花费、KPI 几块都有内容或明确写着「没有」。
- [ ] 切换人员为「李 · SEO」→ 任务只剩李的。
- [ ] 点「导出 XLSX」→ 文件能用 Excel / WPS 打开，没有修复提示，中文正常。
- [ ] **点「AI 审核」**（这一项本地没法验，重点看）：
  - 大约一分钟后出现「AI 审核意见」，分成若干栏（总体判断、逐条任务、询盘、花费…），每条结论带任务编号。
  - 如果显示的是一整段没分栏的文字，并标着「未按结构返回」→ 截图发回来。
  - 如果报错 → 把错误原话发回来。

## 5. 总览的 GEO 卡（本地没法验）

- [ ] 总览页找到「GEO」卡 → 应该列出各 AI 引擎带来的会话数，或写明「这段时间没有任何来自 AI 引擎的访问」。
      如果写的是「GA4 没有同步数据」→ 先到数据看板确认 GA4 同步是否正常。
- [ ] 看卡片下方有没有一条**黄色提示**「可能漏归类的来源…」。有的话把那一行原样发回来 —— 那是系统自己挑出来的、看起来像 AI 引擎但没认出来的来源，不用再逐个悬停去核对。
- [ ] 没有黄色提示、但你明明知道有 AI 来的流量而卡上是 0 → 截图，并到数据看板的 GA4 来源表里把那几行来源也截下来。

## 6. 投入台账

- [ ] 「投入台账」→ 新建一条外链：填一个真实存在的外链页面和它指向的我方页面 → 保存成功。
- [ ] 点「自动核查」→ 几秒后行上出现「自动核查：链接在」或「没找到 / 页面没取到」，并说明原因。人工填的状态不会被它改。
- [ ] 月度汇总里广告费一行有数字（来自 Ads 同步），不同币种分开列。
- [ ] 部署后的第二天再看一眼：昨天登记的那条外链，状态格里的核查时间应该是凌晨（定时核查跑过了）。服务器日志里有一行「[backlinks] 定时核查完成：…」。

## 6.5 数据看板的新诊断：点击率偏低

- [ ] 「数据看板」→ SEO → 子标签里多了「点击率偏低」。点开应该是一张表（关键词 / 页面 / 排名 / 曝光 / 点击率 / 少拿的点击），
      或者一句话：「暂无点击率明显偏低的词」/「首页上曝光够多的词太少，建立不了对比基准」。两种说法意思不同，都属于正常。
- [ ] 表里有内容的话，挑一条到 Search Console 里核对一下排名和点击率是否对得上。

## 6.8 站点管理（多站点第 1 步，经理 / 老板账号）

设置 → API 接入，最上面多了一张「站点管理」。

- 一开始应该显示「还没有登记站点，后台现在用的是服务器配置里的这一个：…」，写的就是现在在用的那个站。
- 点「添加站点」，点 Search Console 资源的输入框，应该能看到账号下的资源可选；GA4 那一栏如果提示列不出来，照提示手填编号。
- 加完第一个新站点后，列表里应该有**两个**站点：原来那个带「默认」标记，新加的不带。**此时看板上的数据应该和加之前完全一样。**
- 对新站点点「补 90 天历史」，等提示出来，那一行应显示「同步成功 · N 行」。失败会直接写原因。
- 第二天早上再看：每个站点的 GSC / GA4 都应该有当天的同步时间。

**选站点**（登记了两个以上站点之后）：

- 数据看板和总览的顶部各多出一个「站点」下拉。切到新站点：SEO 看板的点击 / 曝光、GA4 流量、诊断都应该换成那个站的数；切回来恢复原样。
- 新站点还没补历史时，SEO 顶部的数字应该是「—」，不是 0。
- SEM 看板不随站点变（广告是整个账户的），下拉旁边有一行说明。
- 刷新页面后，下拉应该还停在上次选的站点。
- 选了默认站点以外的站再点 AI 诊断，弹框标题里会提示「AI 目前只读默认站点的数据」—— 这是如实提示，不是出错。

## 6.9 询盘认站点（登记了站点之后）

- 询盘表多了一列「站点」，老询盘都是「—」。点任意一格打开来源弹框，可以选站点；保存后那一格和表头的站点筛选都跟着变。
- 在来源弹框里只填落地页（比如某个站的产品页网址）、站点不选，保存后站点应自动认出来。
- 录入询盘时可以选站点；选了站点、公司还空着时，公司会自动带出。
- 表单线索（插件接好之后）：线索收件箱里每条写着是哪个站点来的；转为询盘后站点那一格带锁，改不了。

## 6.10 按站点看广告花费与询盘（经理 / 老板）

数据看板 → SEM 看板，「真实询盘回报」下面多了一张「按站点：广告花费与询盘」（登记了两个以上站点才出现）。

- 一开始所有系列都在「未归属的系列」一行里。在卡片下方的「系列归属」里给每个系列选它投的是哪个站，选完那一行的花费就落到对应站点上。
- 把各站点的花费加上「未归属」，应该等于上面「账户体检」里的总花费。
- 老询盘都没标站点，所以「没标站点的询盘」一行会比较大，这是正常的；标了站点的询盘才会算到站点上。
- 李 / 陈的账号能看这张表，但不能改归属。
